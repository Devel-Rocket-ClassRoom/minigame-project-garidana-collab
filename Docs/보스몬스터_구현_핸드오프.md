## 2. 현재 확인된 BossMonster 구조

현재 `BossMonster.cs`에는 보스 전용 패턴의 기본 틀이 이미 잡혀 있습니다.

주요 필드와 개념은 다음과 같습니다.

- `public MonsterData data`
  - 보스 체력, 공격력, 이동속도, 보상 정보를 가져오는 ScriptableObject입니다.
- `public event System.Action<float> OnHpChanged`
  - HP 비율 변경 이벤트입니다.
  - 보스 전용 HP 바를 만들 때 이 이벤트를 그대로 활용하면 됩니다.
- `patternDelay`
  - 패턴 사이 대기 시간입니다.
- `lookAtPlayerSpeed`
  - 보스가 플레이어를 바라보는 회전 속도입니다.
- `groundAttackRange`
  - 근거리 바닥/일반 공격 판정 범위입니다.
- `xAttackRange`
  - X 공격 사거리입니다.
- `xAttackAngle`
  - X 공격 각도입니다.
- `jumpAttackRadius`
  - 점프 착지 공격 반경입니다.
- `minionPrefabs`
  - 소환할 하수인 프리팹 배열입니다.
- `summonPoints`
  - 하수인 소환 위치 배열입니다.
- `summonMinCount`, `summonMaxCount`
  - 소환 수 범위입니다.
- `hitEffectPrefab`, `hitEffectPoint`
  - 피격 이펙트 관련 참조입니다.

현재 애니메이터 파라미터로 다음 해시가 준비되어 있습니다.

- `Spawn`
- `isMoving`
- `TakeDamage`
- `Death`
- `GroundAttack`
- `XAttack`
- `JumpAttack`
- `Summon`

현재 애니메이션 이벤트용 메서드로 다음 메서드가 준비되어 있습니다.

- `OnSpawnFinished()`
- `OnGroundAttackHit()`
- `OnXAttackHit()`
- `OnJumpAttackLand()`
- `OnSummonMinions()`

이 메서드들은 보스 애니메이션 클립의 정확한 타이밍에 이벤트로 연결되어야 합니다.

## 3. 현재 BossMonster의 런타임 흐름

현재 코드 기준 흐름은 대략 다음과 같습니다.

1. `Awake()`
   - `NavMeshAgent`, `Animator`, `Player`를 찾습니다.
   - `currentHp = data.maxHp`로 체력을 초기화합니다.
   - `agent.speed = data.moveSpeed`
   - `agent.angularSpeed = lookAtPlayerSpeed`

2. `Start()`
   - 현재는 바로 `animator.SetTrigger(ParamSpawn)`을 호출합니다.

3. `Update()`
   - `isDead`, `!combatStarted`, `patternRunning`이면 아무것도 하지 않습니다.
   - 전투가 시작되어 있고 패턴이 실행 중이 아니면 `FacePlayer()` 후 `PatternRoutine()` 코루틴을 시작합니다.

4. `PatternRoutine()`
   - 이동을 멈춥니다.
   - `patternDelay`만큼 대기합니다.
   - `summonReserved`가 true이면 소환 패턴을 실행합니다.
   - 아니면 `GroundAttack`, `XAttack`, `JumpAttack` 중 하나를 실행합니다.

5. 현재 패턴 선택
   - `GetNextAttackPattern()`은 현재 고정 순환 방식입니다.
   - 순서: `GroundAttack -> XAttack -> JumpAttack -> GroundAttack ...`

6. 2페이즈 진입
   - `TakeHit()`에서 `currentHp <= data.maxHp * 0.5f`가 되면:
     - `phaseTwoStarted = true`
     - `summonReserved = true`
     - `attackMultiplier = 1.5f`

7. 사망
   - `Die()`에서:
     - `isDead = true`
     - `combatStarted = false`
     - `NavMeshAgent` 비활성화
     - `Death` 트리거
     - 자식 콜라이더 비활성화
     - `QuestManager.Instance?.ReportKill(data.questTargetId)`
     - 골드/경험치 지급
     - 5초 뒤 Destroy

## 5. 사용자와 합의된 보스전 컨셉

사용자가 설명한 보스전 의도는 다음과 같습니다.

플레이어가 보스방에 들어오면 보스가 Spawn됩니다.  
하지만 보스방 진입 시점이 곧바로 본격 전투 시작은 아닙니다.  
보스가 Spawn 연출을 재생하고, Spawn이 끝난 뒤 플레이어와 본격적으로 전투를 시작하는 개념입니다.

따라서 최종 전투 흐름은 다음과 같이 잡는 것이 좋습니다.

```text
플레이어 보스방 진입
-> BossRoomTrigger 발동
-> 보스 오브젝트 활성화 또는 Instantiate
-> BossMonster.BeginSpawn()
-> Spawn 애니메이션 재생
-> 애니메이션 이벤트 OnSpawnFinished()
-> combatStarted = true
-> 1페이즈 패턴 루프 시작
-> HP 50% 이하
-> 2페이즈 전환
-> 하수인 1회 소환
-> 이후 소환 없이 강화된 공격 패턴 반복
-> 보스 사망
```

## 6. 권장 보스 상태 구조

현재 `BossMonster`는 bool 상태값으로 흐름을 관리합니다.

현재 존재하는 주요 bool은 다음과 같습니다.

- `isDead`
- `combatStarted`
- `patternRunning`
- `phaseTwoStarted`
- `summonReserved`

기능을 작게 구현할 때는 이 구조로도 가능합니다.  
하지만 보스전은 이후 UI, 문 닫기, 전투 시작 연출, 페이즈 전환, 사망 연출이 붙을 가능성이 높으므로 상태를 조금 더 명확히 나누는 것이 좋습니다.

권장 상태 enum 예시는 다음과 같습니다.

```csharp
private enum BossState
{
    Inactive,
    Spawning,
    PhaseOne,
    PhaseTransition,
    PhaseTwo,
    Dead
}
```

다만 첫 구현에서는 너무 큰 리팩터링을 하지 않아도 됩니다.  
현재 코드 흐름을 최대한 유지한다면 다음 정도만 추가해도 충분합니다.

- `public void BeginSpawn()`
  - 외부 트리거에서 호출합니다.
  - 여기서 Spawn 트리거를 실행합니다.
- `OnSpawnFinished()`
  - Spawn 애니메이션 이벤트에서 호출합니다.
  - 여기서 본격 전투를 시작합니다.
- `EnterPhaseTwo()`
  - HP 50% 이하에서 한 번만 호출합니다.
  - 소환 예약, 공격 강화, 범위 강화, 패턴 딜레이 감소를 처리합니다.

## 7. 보스방 진입 트리거 구상

전투 시작은 `BossMonster` 혼자 판단하지 않는 것이 좋습니다.  
보스방 진입은 별도 스크립트가 담당하는 편이 역할이 명확합니다.

권장 스크립트명:

- `BossRoomTrigger.cs`

권장 위치:

- `Assets/Scripts/Monster/BossRoomTrigger.cs`
또는
- `Assets/Scripts/Boss/BossRoomTrigger.cs`

현재 프로젝트 구조상 `BossMonster.cs`가 `Assets/Scripts/Monster`에 있으므로, 첫 구현은 같은 폴더에 두어도 괜찮습니다.

권장 책임:

- 플레이어가 보스방 Trigger Collider에 들어왔는지 감지
- 한 번만 발동되도록 처리
- 보스 오브젝트가 비활성 상태라면 활성화
- 보스가 프리팹이라면 지정 위치에 Instantiate
- `BossMonster.BeginSpawn()` 호출
- 필요하다면 보스방 입구 문 닫기, BGM 변경, 카메라 연출 등을 나중에 연결

권장 흐름 예시:

```csharp
public class BossRoomTrigger : MonoBehaviour
{
    [SerializeField] private BossMonster boss;
    [SerializeField] private GameObject bossObject;

    private bool triggered;

    private void OnTriggerEnter(Collider other)
    {
        if (triggered || !other.CompareTag("Player"))
        {
            return;
        }

        triggered = true;

        if (bossObject != null)
        {
            bossObject.SetActive(true);
        }

        boss.BeginSpawn();
    }
}
```

이 코드는 예시이며, 실제 구현 시에는 현재 씬의 보스 배치 방식에 맞춰 조정해야 합니다.

## 8. Spawn 시작 방식 변경 방향

현재 `BossMonster.Start()`는 바로 Spawn 트리거를 실행합니다.

```csharp
private void Start()
{
    animator.SetTrigger(ParamSpawn);
}
```

이 구조는 “플레이어가 보스방에 들어온 뒤 Spawn”이라는 현재 기획과 맞지 않습니다.

권장 변경 방향:

- `Start()`에서 Spawn을 자동 실행하지 않습니다.
- `BeginSpawn()`이라는 public 메서드를 추가합니다.
- `BossRoomTrigger`가 이 메서드를 호출합니다.
- `BeginSpawn()` 호출 전까지는 전투 루프가 돌지 않습니다.

권장 개념:

```csharp
public void BeginSpawn()
{
    if (isDead || combatStarted)
    {
        return;
    }

    animator.SetTrigger(ParamSpawn);
}
```

다만 Spawn 중 중복 호출을 막으려면 `spawnStarted` 같은 bool도 두는 것이 좋습니다.

## 9. Spawn 종료 후 전투 시작

현재 `BossMonster`에는 이미 `OnSpawnFinished()`가 있습니다.

```csharp
public void OnSpawnFinished()
{
    combatStarted = true;
}
```

이 메서드는 Spawn 애니메이션 클립 끝부분에 애니메이션 이벤트로 연결해야 합니다.

연결 목적:

- Spawn 연출이 끝나기 전에는 보스가 공격하지 않습니다.
- Spawn 연출이 끝난 후 `combatStarted = true`가 되며 패턴 루프가 시작됩니다.

주의:

- 애니메이션 이벤트가 연결되지 않으면 보스가 영원히 전투를 시작하지 않을 수 있습니다.
- 임시 테스트용으로는 `BeginSpawn()`에서 `StartCoroutine`으로 일정 시간 뒤 전투 시작하는 fallback을 둘 수 있지만, 최종 구조는 애니메이션 이벤트가 더 좋습니다.

## 10. 패턴 선택 규칙

현재 패턴은 고정 순환입니다.

```text
GroundAttack -> XAttack -> JumpAttack -> 반복
```

사용자와 논의한 결과, 다음 방식으로 바꾸는 것이 좋습니다.

1페이즈:

- 플레이어가 가까우면 `GroundAttack`
- 중거리면 `XAttack`
- 멀면 `JumpAttack`
- 완전 랜덤보다는 거리 기반으로 선택
- 같은 패턴이 너무 자주 반복되지 않도록 보정

거리 기준 예시:

```text
distance <= groundAttackRange
-> GroundAttack

distance <= xAttackRange
-> XAttack

distance > xAttackRange
-> JumpAttack
```

다만 이렇게만 하면 플레이어 거리에 따라 같은 패턴만 반복될 수 있습니다.  
그래서 아래처럼 후보 기반이 더 좋습니다.

```text
가까움:
  후보: GroundAttack, XAttack

중거리:
  후보: XAttack, JumpAttack

원거리:
  후보: JumpAttack
```

그리고 마지막 사용 패턴을 저장해서 같은 패턴 연속 사용을 줄이면 보스전이 덜 단조롭습니다.

권장 필드:

```csharp
private BossAttackType? lastAttackPattern;
```

또는 nullable이 부담스럽다면:

```csharp
private BossAttackType lastAttackPattern;
private bool hasLastAttackPattern;
```

## 11. 1페이즈 패턴 의도

1페이즈는 플레이어가 보스의 공격을 읽고 적응하는 단계입니다.

권장 의도:

- `GroundAttack`
  - 근접 압박용입니다.
  - 플레이어가 보스에게 붙어 있을 때 사용합니다.
  - 범위는 작지만 회피 타이밍을 요구합니다.

- `XAttack`
  - 전방 중거리 공격입니다.
  - 플레이어가 적당히 떨어져 있을 때 사용합니다.
  - `xAttackAngle`로 부채꼴 또는 전방 판정을 만들 수 있습니다.

- `JumpAttack`
  - 거리 벌리는 플레이어를 압박하는 공격입니다.
  - 착지 지점 주변 `jumpAttackRadius`로 데미지를 줍니다.
  - 현재 코드는 실제 점프 이동이 구현되어 있지는 않고, 착지 시점 이벤트 판정만 있습니다.
  - 나중에 실제 점프 이동/돌진을 추가할지 확인해야 합니다.

## 12. 2페이즈 방향

사용자와 합의한 2페이즈 방향은 다음과 같습니다.

- HP 50% 이하에서 2페이즈 진입
- 2페이즈 진입 시 하수인을 1회만 소환
- 이후에는 다시 소환하지 않음
- 2페이즈부터는 기존 공격들의 범위와 데미지를 증가
- 새 패턴을 많이 늘리기보다, 기존 패턴이 더 위험해지는 방식

현재 코드에는 이미 다음 흐름이 있습니다.

```csharp
if (!phaseTwoStarted && currentHp <= data.maxHp * 0.5f)
{
    phaseTwoStarted = true;
    summonReserved = true;
    attackMultiplier = 1.5f;
}
```

이 흐름은 방향이 맞습니다.  
다만 다음 보강이 필요합니다.

- 2페이즈 진입 처리를 `EnterPhaseTwo()` 메서드로 분리
- 소환은 1회만 실행되도록 명확히 보장
- 소환 이후에는 소환 패턴이 일반 패턴 풀에 들어가지 않게 유지
- 2페이즈 진입 시 범위 증가 적용
- 2페이즈 진입 시 패턴 딜레이 감소 적용

권장 2페이즈 강화 예시:

```text
attackMultiplier: 1.5
groundAttackRange: 기존값 * 1.2
xAttackRange: 기존값 * 1.2
xAttackAngle: 기존값 + 10~20도
jumpAttackRadius: 기존값 * 1.25
patternDelay: 기존값 * 0.75
```

주의:

- 필드 값을 직접 곱해서 바꾸면 인스펙터 원본 값과 런타임 값이 섞일 수 있습니다.
- 가능하면 `phaseTwoGroundAttackRangeMultiplier` 같은 별도 배율 필드를 두는 편이 좋습니다.

예시:

```csharp
[Header("Phase Two")]
[SerializeField] private float phaseTwoAttackMultiplier = 1.5f;
[SerializeField] private float phaseTwoRangeMultiplier = 1.2f;
[SerializeField] private float phaseTwoJumpRadiusMultiplier = 1.25f;
[SerializeField] private float phaseTwoPatternDelayMultiplier = 0.75f;
```

그리고 판정 시점에 현재 페이즈 배율을 적용하면 인스펙터 값 보존이 쉽습니다.

## 14. 애니메이션 이벤트 연결 계획

보스 공격은 코드 타이머보다 애니메이션 이벤트 중심으로 가는 것이 좋습니다.  
현재 일반 몬스터 `BaseMonster`도 실제 데미지 적용은 `OnAttackHit()` 애니메이션 이벤트 흐름으로 동작합니다.

보스도 같은 철학을 유지하는 것이 좋습니다.

필요한 이벤트:

### Spawn 애니메이션

클립 끝부분:

```text
OnSpawnFinished
```

역할:

- Spawn 연출 종료
- 본격 전투 시작

### GroundAttack 애니메이션

실제 타격 프레임:

```text
OnGroundAttackHit
```

역할:

- 플레이어가 `groundAttackRange` 안에 있으면 데미지

### XAttack 애니메이션

검기 또는 X 공격이 실제로 나가는 프레임:

```text
OnXAttackHit
```

역할:

- 플레이어가 `xAttackRange` 안에 있고
- 보스 전방 `xAttackAngle` 안에 있으면 데미지

### JumpAttack 애니메이션

착지 프레임:

```text
OnJumpAttackLand
```

역할:

- `Physics.OverlapSphere`로 `jumpAttackRadius` 안의 플레이어에게 데미지

### Summon 애니메이션

소환 연출이 터지는 프레임:

```text
OnSummonMinions
```

역할:

- 하수인 프리팹을 소환 포인트에 생성

주의:

- 현재 `WaitForAnimationEventOrFallback()`은 2초 대기만 합니다.
- 이 함수는 "애니메이션 이벤트 연결 전에도 패턴 루프가 멈추지 않게 하는 임시 대기"입니다.
- 실제 구현에서는 패턴 종료 이벤트까지 연결하거나, 애니메이션 길이 기반 대기로 바꾸는 것을 검토해야 합니다.

## 15. 현재 WaitForAnimationEventOrFallback의 한계

현재 코드는 각 패턴 실행 후 무조건 2초를 기다립니다.

```csharp
private IEnumerator WaitForAnimationEventOrFallback()
{
    // 1차 구현에서는 애니메이션 이벤트 연결 전에도 패턴이 멈추지 않게 임시 대기시간 사용
    yield return new WaitForSeconds(2f);
}
```

이 방식은 테스트에는 편하지만, 다음 문제가 생길 수 있습니다.

- 애니메이션이 1초인데 2초 기다리면 보스가 굼뜹니다.
- 애니메이션이 3초인데 2초만 기다리면 다음 패턴이 겹칠 수 있습니다.
- 실제 타격 이벤트와 패턴 종료가 분리되어 있지 않습니다.

권장 개선 방향:

1. 단기:
   - 패턴별 대기 시간을 serialized field로 분리합니다.
   - 예: `groundAttackDuration`, `xAttackDuration`, `jumpAttackDuration`, `summonDuration`

2. 중기:
   - 애니메이션 이벤트로 `OnPatternAnimationFinished()`를 호출합니다.
   - 코루틴은 이 이벤트가 올 때까지 기다립니다.

3. 최종:
   - Animator 상태 길이 또는 StateMachineBehaviour를 활용합니다.
   - 다만 현재 프로젝트 규모에서는 애니메이션 이벤트 방식이 더 단순합니다.

첫 구현에서는 1번 또는 2번이 좋습니다.

## 17. 보스 HP 바와 기존 MonsterHpBar 관계

현재 `MonsterHpBar`는 `BossMonster`도 처리할 수 있습니다.

```csharp
private BaseMonster _monster;
```

하지만 보스 전용 상단 HP바를 만들 경우 다음 중 하나를 선택해야 합니다.

선택 A:

- 보스 머리 위 HP바를 제거하거나 비활성화
- 상단 보스 HP바만 사용

선택 B:

- 머리 위 HP바와 상단 HP바를 둘 다 사용
- 다만 화면이 지저분해질 수 있습니다.

권장:

- 보스는 상단 전용 HP바만 사용
- 일반 몬스터는 기존 머리 위 HP바 유지

실제 적용할 때는 `Demon_Boss Variant`의 자식 HP바 오브젝트가 있는지 확인하고, 있으면 비활성화 여부를 정해야 합니다.

## 18. BossMonster와 BaseMonster의 차이

`BaseMonster`는 일반 몬스터용입니다.

일반 몬스터 흐름:

- 배회
- 감지
- 추적
- 공격 범위 내 공격
- 피격 넉백
- 사망 시 콜라이더 비활성화
- 보상 지급
- 퀘스트 드랍 처리
- `SinkAndDestroy()`

`BossMonster`는 현재 독립 구현입니다.

보스 흐름:

- 스폰 연출
- 패턴 루프
- 페이즈 전환
- 하수인 소환
- 보스 전용 HP 이벤트
- 사망 처리

주의:

- `BossMonster.ProcessDrop()`은 현재 골드/경험치만 지급합니다.
- 일반 몬스터처럼 `questDrops`를 처리하지 않습니다.
- 보스가 퀘스트 아이템을 드랍해야 한다면 `BaseMonster.ProcessDrop()`의 questDrops 흐름을 참고해서 보스에도 추가해야 합니다.

- 패턴 딜레이 감소
- 이후 소환 패턴 반복 금지

- 보스 이름 표시

### 8단계: 애니메이션 이벤트 연결

- `OnGroundAttackHit`
- `OnXAttackHit`
- `OnJumpAttackLand`
- `OnSummonMinions`

### 9단계: 테스트

## 21. 구현할 때 주의할 점

### NullReference 방지

현재 `BossMonster.Awake()`는 `data`와 `Player`가 반드시 있다고 가정합니다.

```csharp
player = GameObject.FindWithTag("Player").transform;
currentHp = data.maxHp;
```

`data`가 비어 있거나 Player 태그 오브젝트가 없으면 바로 예외가 날 수 있습니다.  
실제 구현 시 최소한 방어 로그를 넣는 것이 좋습니다.

예:

```csharp
if (data == null)
{
    Debug.LogError($"{name} has no MonsterData assigned.", this);
    enabled = false;
    return;
}
```

### Spawn 전 보스 상태

보스가 씬에 처음부터 활성화되어 있으면 `Awake()`는 실행됩니다.  
다만 전투는 `BeginSpawn()` 전까지 시작하지 않아야 합니다.

선택지:

- 보스 오브젝트는 비활성으로 두고, 보스방 진입 시 활성화
- 보스 오브젝트는 활성으로 두되, 렌더러/애니메이션 상태를 Spawn 전 대기 상태로 둠

첫 구현은 보스 오브젝트를 비활성으로 두고 보스방 진입 시 활성화하는 방식이 단순합니다.

### 하수인 소환 후 보스 패턴

2페이즈 진입 후 하수인 소환은 1회만입니다.  
이후에는 소환을 다시 하지 않습니다.

현재 `summonReserved` 방식은 이 의도와 잘 맞습니다.  
다만 `summonReserved`가 true인 동안 보스가 죽거나 패턴이 끊기는 경우도 고려해야 합니다.

### 데미지와 범위 증가 방식

데미지는 이미 `attackMultiplier`가 있습니다.  
범위 증가는 필드 자체를 바꾸기보다 판정 시 배율을 적용하는 방식이 더 안전합니다.

예:

```csharp
float currentGroundRange = groundAttackRange * CurrentRangeMultiplier;
```

### 보스 사망 보상

현재 `BossMonster.ProcessDrop()`은 다음만 합니다.

- 골드 지급
- 경험치 지급

일반 몬스터의 퀘스트 아이템 드랍 흐름은 없습니다.  
보스가 특별 아이템을 드랍해야 한다면 별도 구현이 필요합니다.

## 22. 다음 Codex에게 바로 줄 수 있는 작업 지시 예시

다른 PC의 Codex에서 이어서 작업할 때는 아래처럼 요청하면 좋습니다.

```text
Docs/보스몬스터_구현_핸드오프.md를 먼저 읽고, 현재 BossMonster.cs와 SampleScene의 보스 연결 상태를 확인해줘.
아직 코드는 수정하지 말고, 실제로 어떤 파일을 어떤 순서로 고치면 좋을지 먼저 정리해줘.
```

구현까지 맡길 때는 아래처럼 요청하면 좋습니다.

```text
Docs/보스몬스터_구현_핸드오프.md 기준으로 보스 구현 1단계를 진행해줘.
먼저 BossMonster.cs에서 Start 자동 Spawn을 BeginSpawn 방식으로 바꾸고,
BossRoomTrigger.cs를 추가해서 플레이어가 보스방에 들어오면 Spawn이 시작되게 해줘.
수정 전에는 어떤 파일을 고칠지 말해줘.
```

보스 HP바 작업을 따로 맡길 때:

```text
Docs/보스몬스터_구현_핸드오프.md 기준으로 보스 전용 HP 바를 구현해줘.
BossMonster.OnHpChanged를 사용하고, 일반 MonsterHpBar와 역할이 겹치지 않게 상단 UI 전용으로 만들어줘.
```

2페이즈 작업만 맡길 때:

```text
Docs/보스몬스터_구현_핸드오프.md 기준으로 BossMonster의 2페이즈 로직을 정리해줘.
HP 50% 이하에서 하수인을 1회만 소환하고, 이후에는 공격 데미지와 범위, 패턴 속도만 강화되게 해줘.
```

## 23. 현재 대화에서 확정된 결정 요약

확정된 방향:

- 보스방 진입 시 보스가 Spawn됩니다.
- Spawn 연출이 끝난 뒤 본격 전투가 시작됩니다.
- 패턴 선택은 거리 기반으로 바꿉니다.
- 1페이즈는 `GroundAttack`, `XAttack`, `JumpAttack` 중심입니다.
- 2페이즈는 HP 50% 이하에서 진입합니다.
- 2페이즈 진입 시 하수인을 1회만 소환합니다.
- 2페이즈 이후에는 다시 소환하지 않습니다.
- 2페이즈에서는 공격 데미지와 범위를 증가시킵니다.
- 보스 전용 상단 HP 바를 만듭니다.
- 애니메이션 이벤트 연결이 매우 중요합니다.

아직 확정되지 않은 것:

- 보스가 씬에 비활성 배치될지, 프리팹으로 Instantiate될지
- 보스방 문 닫기/봉쇄 연출을 지금 구현할지
- 보스 BGM 전환을 지금 구현할지
- 보스 HP바 디자인
- 하수인 종류와 수
- 소환 위치 개수
- 점프 공격이 실제 위치 이동을 할지, 현재 위치 착지 판정만 할지
- 보스 사망 후 포탈/엔딩/클리어 UI를 띄울지

## 24. 가장 중요한 다음 한 걸음

다음 작업의 첫 목표는 크게 잡지 말고 다음 하나로 잡는 것이 좋습니다.

```text
플레이어가 보스방에 들어오면 보스 Spawn 애니메이션이 재생되고,
Spawn 종료 후 보스가 거리 기반으로 3개 공격 패턴을 반복한다.
```

이 목표가 안정적으로 동작한 뒤에:

1. 2페이즈 하수인 소환
2. 2페이즈 공격 강화
3. 보스 전용 HP 바
4. 사망 연출/보상/클리어 처리

순서로 붙이는 것이 안전합니다.

## 25. 작업 모드 주의

사용자는 "구상부터 해보자", "작업을 시작하지 말고"라고 말하면 실제 코드 수정을 원하지 않는 경우가 많습니다.  
따라서 다른 PC의 Codex는 이 문서를 읽은 뒤에도 사용자가 명시적으로 구현을 요청하기 전까지는 코드나 씬 파일을 수정하지 않는 것이 좋습니다.

사용자가 구현을 요청하면:

1. 현재 코드와 씬 연결 상태를 먼저 확인합니다.
2. 수정할 파일을 먼저 말합니다.
3. 필요한 파일만 좁게 수정합니다.
4. 불필요한 리팩터링은 하지 않습니다.
5. 가능하면 `dotnet build Assembly-CSharp.csproj`로 스크립트 컴파일을 확인합니다.
